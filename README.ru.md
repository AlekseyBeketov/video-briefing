# Video Briefing

[Инструкция на английском](README.md)

**Настройка через AI-агента:** скопируйте готовый prompt на английском для [Codex CLI](docs/agent-prompts/codex.md#copyable-prompt), [Claude Code](docs/agent-prompts/claude-code.md#copyable-prompt) или [Hermes](docs/agent-prompts/hermes.md#copyable-prompt).

Video Briefing — Python CLI и опциональный MCP-сервер для работы с доказательствами из транскриптов видео с таймкодами. Инструмент сохраняет субтитры или явно запрошенную локальную расшифровку речи, а затем позволяет искать и читать исходные сегменты с временными границами. Агент или пользователь может использовать эти фрагменты для ответа с опорой на источник.

Обычный сценарий `ingest`, `search` и `read` не вызывает языковую модель. Отдельные команды `brief` и `ask` вызывают настроенную модель и не являются основным evidence-first сценарием.

## Требования

- Python 3.11, 3.12, 3.13 или 3.14.
- [`uv`](https://docs.astral.sh/uv/getting-started/installation/) для установки из checkout по инструкции ниже.
- Доступ в интернет для установки Python-зависимостей, необязательной загрузки выбранных моделей речи и получения публичных субтитров YouTube. Инструмент не обходит блокировки, требования авторизации или лимиты запросов.

CI проверяет Python 3.11–3.14 на Ubuntu. Проект пока не определил более широкую матрицу поддерживаемых операционных систем.

## Установка из репозитория

```sh
git clone https://github.com/AlekseyBeketov/video-briefing.git
cd video-briefing
uv sync --frozen
uv run video-briefing --help
uv run video-briefing doctor
```

`uv sync --frozen` устанавливает версии из `uv.lock` в окружение этого checkout. `doctor` показывает доступность ASR runtime и проверяет хэши моделей; FFmpeg/FFprobe относятся только к старому режиму. Команда не обращается к YouTube, не скачивает модели, не загружает веса модели в память и не выполняет распознавание.

## Быстрый старт: субтитры YouTube

Замените `VIDEO_ID` на ID публичного видео YouTube, для которого доступны субтитры с таймкодами.

```sh
VIDEO='https://www.youtube.com/watch?v=VIDEO_ID'
uv run video-briefing ingest "$VIDEO"
uv run video-briefing search "$VIDEO" 'основные идеи и решения'
uv run video-briefing read "$VIDEO" 120 180
```

По умолчанию используется extractor `captions_api` на базе `youtube-transcript-api`; язык субтитров по умолчанию — русский. `ingest` сохраняет исходные данные локально. `search` возвращает ограниченный набор подходящих сегментов транскрипта, а `read` — ограниченные сегменты из заданного интервала. Оба результата содержат текст и метаданные времени. Перед утверждением проверьте цитату вместе с окружающим контекстом.

Если субтитры отсутствуют или доступ заблокирован, автоматического перехода к описанию видео, cookies, сессии браузера, proxy или другому extractor нет. Дополнительный вариант `baoyu` нужно явно выбрать через `--variant baoyu` и настроить отдельно.

## Быстрый старт: локальный MP4

Локальная расшифровка требует явного opt-in. Установите runtime и русскую модель одной командой из репозитория:

```sh
uv run --frozen --extra asr video-briefing setup-asr --languages ru --yes
uv run --frozen --extra asr video-briefing doctor
uv run --frozen --extra asr video-briefing ingest /path/to/video.mp4 --local-asr --source-language ru
```

Выберите `en` для английского или `ru,en`, чтобы установить обе модели. Установщик загружает только выбранные закреплённые версии моделей в каталог пользовательских данных и сверяет размер и SHA-256. Внешний ASR-бинарник не нужен. При запуске без `--languages` в интерактивном терминале команда предлагает профиль по локали ОС и спрашивает перед загрузкой. В неинтерактивном режиме язык обязателен. `--yes` подтверждает только показанную загрузку публичной модели.

Для русского используется GigaAM v3 e2e-RNN-T Q8_0 (274 МБ, MIT). Для английского — NVIDIA Parakeet TDT-CTC 110M Q8_0 (135 МБ, CC-BY-4.0; атрибуция отображается при установке и указана в [карточке модели](https://huggingface.co/handy-computer/parakeet-tdt_ctc-110m-gguf)). Обе модели работают локально, но требуют знать язык речи. Установка не определяет язык произвольного видео. Если установлены обе модели, укажите `--source-language`.

Пример с английской моделью:

```sh
uv run --frozen --extra asr video-briefing setup-asr --languages en --yes
uv run --frozen --extra asr video-briefing ingest /path/to/video.mp4 --local-asr --source-language en
```

Используйте возвращённый SHA-256 медиафайла, чтобы искать или читать сохранённые локальные данные:

```sh
uv run video-briefing search MEDIA_SHA256 'тема'
uv run video-briefing read MEDIA_SHA256 120 180
```

Локальный ASR обрабатывает аудио на этой машине. Таймкоды обозначают окна обработки длительностью 24 секунды, а не выравнивание до слов; распознавание может содержать ошибки.

Для постоянного окружения установите runtime один раз через `uv sync --frozen --extra asr`. Если локальные MP4 будут обрабатываться через MCP, установите оба extra командой `uv sync --frozen --extra mcp --extra asr`, затем запустите `setup-asr`. Управляемый маршрут использует PyAV и не требует FFmpeg или FFprobe. Параметры `--transcribe-cli`/`--model` и переменные `VIDEO_BRIEFING_TRANSCRIBE`/`VIDEO_BRIEFING_ASR_MODEL` остаются для совместимости со старыми установками.

## Подключение агента

Опциональный MCP-сервер позволяет MCP-совместимому агенту вызывать инструменты Video Briefing через локальный stdio-процесс. Для установки MCP extra из репозитория выполните:

```sh
uv sync --frozen --extra mcp
uv run video-briefing --version
uv run video-briefing doctor
```

MCP-сервер предоставляет инструменты `ingest_youtube`, `ingest_local_mp4`, `search_video_evidence`, `read_video_evidence` и `validate_video_claims`. Если агент поддерживает allowlist инструментов для сервера, в режиме только на чтение включите `search_video_evidence`, `read_video_evidence` и `validate_video_claims`. Если нет — оставьте штатные подтверждения вызовов и не разрешайте ingestion без необходимости.

Смотрите [общее руководство по подключению](docs/agent-integration.md) и копируемые инструкции для [Hermes](docs/agent-prompts/hermes.md), [Codex CLI](docs/agent-prompts/codex.md) и [Claude Code](docs/agent-prompts/claude-code.md).

Сам MCP-сервер не вызывает модель. Его данные становятся частью контекста вызывающего агента, поэтому провайдер агента может получить фрагменты транскрипта. Перед использованием частных или чувствительных источников проверьте правила обработки данных провайдером.

## Конфигурация и данные

По умолчанию evidence хранится вне репозитория в каталоге пользовательских данных операционной системы:

- macOS: `~/Library/Application Support/VideoBriefing`
- Windows: `%LOCALAPPDATA%/VideoBriefing`
- Linux и другие Unix-системы: `$XDG_DATA_HOME/video-briefing`, или `~/.local/share/video-briefing`, если `XDG_DATA_HOME` не задан

Задайте `VIDEO_BRIEFING_DATA_HOME`, чтобы использовать другой приватный каталог. Если CLI и MCP-сервер должны читать общий кэш, укажите одинаковое значение в окружении обоих процессов. Не размещайте данные в публичном или отслеживаемом Git каталоге.

Управляемые ASR-модели находятся в `<VIDEO_BRIEFING_DATA_HOME>/asr/models` или в системном каталоге пользовательских данных из списка выше. Указывать пути моделей вручную не нужно. Продвинутые старые установки могут по-прежнему использовать `VIDEO_BRIEFING_TRANSCRIBE`, `VIDEO_BRIEFING_ASR_MODEL`, `VIDEO_BRIEFING_FFMPEG` и `VIDEO_BRIEFING_FFPROBE`.

Необязательные `brief` и `ask` используют Ollama-совместимый endpoint и параметры из `config/experiment.json` по умолчанию. Перед запуском проверьте этот конфиг. Для облачной или не loopback-модели требуется явный флаг `--allow-cloud`, поскольку провайдер может получить фрагменты транскрипта и вопрос. Команда `ask` использует кэш и не загружает отсутствующий источник; сначала выполните `ingest`. Эти необязательные команды генерации не заменяют обычный сценарий работы с источниками.

## Доказательства и ограничения

- Video Briefing работает с субтитрами с таймкодами или с явно выбранной локальной расшифровкой аудио. Инструмент не анализирует кадры, не проверяет утверждения по независимым источникам и не гарантирует полноту автоматических субтитров.
- Проверка цитаты подтверждает совпадение текста, ID сегментов, источника и временных границ с сохранённым evidence. Она не доказывает, что пересказ семантически подтверждён или что внешний факт истинен.
- Если в кэше нет источника, его нужно обработать до запуска `search`, `read` или `ask`.
- YouTube может не предоставить субтитры, запросить авторизацию, блокировать анонимный запрос или ограничить частоту запросов. Остановитесь при такой ошибке; не обходите ограничения через cookies или proxy.
- Проект открыт под лицензией MIT; см. файл [LICENSE](LICENSE). У сторонних моделей распознавания отдельные лицензии, указанные выше.

## Решение проблем

**`doctor` сообщает об отсутствии `youtube-transcript-api`.** Запустите `uv sync --frozen` из корня репозитория и повторите проверку. `doctor` проверяет локальные зависимости, но не сетевой доступ к YouTube.

**При поиске или чтении нет подходящего evidence в кэше.** Сначала выполните `video-briefing ingest` для URL или MP4. Проверьте, что язык и вариант совпадают с сохранённым источником.

**Субтитры YouTube недоступны или запрос заблокирован.** Инструмент вернёт ошибку источника. Попробуйте позже или выберите другой доступный вам источник; инструмент не использует cookies, файлы авторизации или proxy для обхода ограничений.

**MCP-сервер отсутствует или агент не может подключиться.** Установите extra `mcp`, проверьте, что команда в конфигурации указывает на исполняемый файл `video-briefing-mcp` из нужного окружения, затем перезапустите или обновите соединение в агенте. Выполните `video-briefing doctor` в том же окружении, где запускается сервер.

**Для локального MP4 не найдена модель ASR.** Запустите `uv run --frozen --extra asr video-briefing setup-asr --languages ru --yes` или выберите `en` для английского. Проверьте SHA установленной модели командой `doctor`. Если установлены обе модели, передайте `--source-language ru` или `--source-language en`; язык видео автоматически не угадывается.

**`setup-asr` сообщает об отсутствии runtime или совместимого wheel.** Из корня репозитория выполните `uv sync --frozen --extra asr` и повторите команду. Python-пакет публикует готовые native wheels для macOS arm64/x86_64, Linux x86_64/aarch64 и Windows x86_64; реальная проверка моделей в этом репозитории проведена на macOS arm64 с Python 3.14. На другой платформе сообщите точную ошибку `uv`, не устанавливая автоматически компилятор или системный пакет.

**Загрузка модели оборвалась или SHA не совпал.** Установщик удалит временную часть файла и не активирует модель. Повторите загрузку при стабильном соединении. Если целевой файл уже существует с другими данными, установщик оставит его как есть; перед повтором самостоятельно переместите или сохраните этот файл.
