# Historical smoke record and current limits

The dated results below are a historical smoke record, not a description of the default workflow or a current readiness claim. The current default is source-first: ingest timed evidence, retrieve bounded passages, and let the calling agent synthesize. Optional `brief` and `ask` model-generation commands are separate.

Verified working path (Wednesday, October 7, 2026): the then-checked-in Python CLI extracted anonymous Russian timed captions with `youtube-transcript-api==1.2.4`, stored provenance and source hash, created a cited Russian briefing, then answered grounded questions from the saved transcript. The model endpoint was cloud-backed: requested `gemma4:31b-cloud`, returned model `gemma4:31b`. This was not offline inference.

The summary and two fixed follow-up examples are recorded in `reports/production-acceptance.md`; private raw evidence stays in ignored `artifacts/private/`.

The independent reviews recorded below are historical. Passing tests and a successful smoke do not, by themselves, establish semantic citation support, complete retrieval recall, exhaustive negative answers, stable extraction across sources, or production readiness. Their dated findings are preserved in `reports/spec-review.md`, `reports/code-review.md`, and `reports/review-findings.json`; check the current code and tests before treating a finding as open. Never claim that Q&A has proven a topic absent merely because retrieval abstained. Never attribute captions to a named person without source evidence.

Use the current README and `video-briefing doctor` for setup. The MCP interface distinguishes unavailable source, blocked source, and authentication-required errors; it does not read cookies or credential files. Do not use cookies, credentials, proxies, or paid fallback to bypass a source error. The optional Baoyu path is distinct from the default captions API and should only be used when its installed dependencies and provenance are clear.
