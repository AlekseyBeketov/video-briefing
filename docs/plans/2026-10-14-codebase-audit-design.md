# Дизайн устранения подтверждённых проблем кодовой базы

## Цель

Репозиторий `AlekseyBeketov/video-briefing` — Python-пакет с CLI и MCP-интерфейсом для локального извлечения, неизменяемого хранения и поиска видео-свидетельств, а также экспериментальной генерации кратких обзоров и ответов. Этот дизайн задаёт ограниченный набор исправлений, чтобы ошибки было проще диагностировать, результаты benchmark не раскрывались через обычные права доступа и не затирали историю, а проверки запускались до слияния.

## Исходные данные

Текущая ветка `main` совпадает с `origin/main` на `c6bec82d1cbaabc88c9612b669fd1df7bee916e0`. До исправлений прошли 172 теста на Python 3.11, 3.13 и 3.14; `compileall`, `uv lock --check --offline` и `uv build --offline` успешны. `video-briefing doctor` сообщает об установленной обязательной зависимости и возвращает 0.

В рабочем дереве уже есть незакоммиченные пользовательские изменения в `reports/production-acceptance.md`, несколько новых отчётов и `.codegraph/`. Они не относятся к этой работе и должны оставаться вне всех коммитов.

## Рассмотренные подходы

Минимальный вариант исправляет только сообщения ошибок и добавляет регрессионные тесты, откладывая линтер и CI. Он затрагивает меньше файлов, но оставляет согласованный пробел в автоматических проверках.

Рекомендуемый вариант исправляет три подтверждённых поведения, устраняет доказанно мёртвый и неиспользуемый код, добавляет целевые тесты, Ruff и GitHub Actions. Он покрывает критерии аудита, исправлений и проверяемости, не меняя извлечение источников, форматы свидетельств или экспериментальные генераторы.

Широкая переработка истории и публичной готовности дополнительно редактировала бы абсолютные пути в исторических записях и принимала бы решение о лицензии. Это отдельные решения владельца проекта: исследовательские материалы сохраняются, а лицензию нельзя выбирать за пользователя.

## Выбранный дизайн

В `src/video_briefing/cli.py` команда `doctor` будет возвращать ненулевой код, если отсутствует обязательный `youtube-transcript-api`. Недоступность необязательных инструментов локального ASR останется диагностической и сама по себе не будет считаться ошибкой.

В `src/video_briefing/adapters/captions_api.py` ожидаемые отказы получения титров получат отдельные типы ошибок с безопасными сообщениями. `src/video_briefing/mcp_server.py` отобразит эти типы и безопасный `LocalASRError` в стабильные коды ошибок; неизвестные исключения останутся обобщёнными, чтобы не раскрывать внутренние данные. CLI и поведение успешных операций не меняются.

Benchmark CLI сейчас пишет прогресс и финальные файлы с фиксированными именами в один каталог по умолчанию. `Path.write_text` создаёт файлы с обычными правами процесса, а повторный запуск использует те же имена. Команда будет создавать отдельный каталог запуска с уникальным UTC-временем и случайным суффиксом, сохраняя неудачный прогресс для диагностики. Новый каталог запуска будет иметь режим `0700`, новые каталоги и файлы внутри него будут создаваться ограниченно; временные файлы будут уникальными, закрытыми от других пользователей и заменять конечный файл атомарно. Уже существующие каталоги назначения не будут менять права. Схемы JSON и формат краткого обзора сохраняются; CLI выведет фактические пути созданного запуска.

Подтверждённая очистка ограничится неиспользуемым `_tool_version` в `cli.py`, неиспользуемыми импортами в `local_asr.py` и `tests/test_mcp_server.py`, а также неиспользуемой привязкой `platform` в адаптере Baoyu. Исторические заметки, примеры, ресурсы, пользовательские данные и спорные параметры не удаляются.

В `pyproject.toml` появится закреплённый Ruff и явный набор проверок ошибок и неиспользуемого кода. В тесте MCP опциональные импорты будут организованы так, чтобы линтер мог проверять весь набор тестов без подавления правил. Новый workflow в `.github/workflows/ci.yml` установит проект из lock-файла и запустит Ruff, тесты с MCP, компиляцию Python и сборку на Python 3.11–3.14.

## Проверки и границы

Регрессионные тесты проверят ненулевой статус `doctor` при отсутствующей обязательной зависимости, соответствие ожидаемых ошибок MCP стабильным кодам, режимы benchmark-файлов на POSIX, отдельные каталоги для повторных запусков и корректность путей в CLI-ответе. Неудачный запуск по-прежнему сохраняет прогресс.

После исправлений повторно выполняются тесты на Python 3.11, 3.13 и 3.14, Ruff, `compileall`, проверка lock-файла, `uv build` и `git diff --check`. CI дополнительно проверит Python 3.12. Локальная виртуальная среда репозитория уже была затронута первоначальным неудачным запуском `uv`: `.venv` заменилась с Python 3.9 на Python 3.14 и осталась без установленных зависимостей. Дальнейшие команды используют отдельные окружения в `/tmp`, чтобы не менять её повторно.

В tracked-истории найдены абсолютные пути `/Users/...`; также не найден файл лицензии. Эти факты будут отражены в аудите, но сами данные не редактируются и лицензионное решение не принимается.

## Решения

- Решение: ограничиться подтверждёнными исправлениями и проверками; сохранить существующую архитектуру генерации и форматы данных. Обоснование: пользователь просит поддерживаемую кодовую базу без переписывания работающих частей. Дата: 2026-10-14.
- Решение: создавать уникальный каталог для каждого CLI-запуска benchmark. Обоснование: фиксированные пути прогресса и результатов приводят к тихой замене предыдущего запуска; протокол проекта рассматривает результаты каждого запуска отдельно. Дата: 2026-10-14.
- Решение: не редактировать старые отчёты с локальными путями и не добавлять лицензию. Обоснование: это исторические пользовательские сведения и отдельное решение владельца. Дата: 2026-10-14.
- Решение: аудит, дизайн, план и каждая группа исправлений оформляются отдельными коммитами непосредственно в `origin/main`; в коммиты входят только созданные для этой задачи файлы. Обоснование: прямое требование пользователя. Дата: 2026-10-14.
